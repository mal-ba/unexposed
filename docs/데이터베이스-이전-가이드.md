# 데이터베이스 이전 가이드 (새 Supabase + Cloudflare R2)

## 왜 옮기나요

예전 Supabase 프로젝트가 무료 한도를 넘어서 멈췄습니다. 2026-09-20 백업을 보면 데이터베이스는 표 하나에 많아야 148줄, 파일 저장소는 3개(약 29MB)뿐이라 **용량** 문제는 아니었습니다. 원인은 **전송량(Egress, 월 5GB)** 입니다. 옷장에 올라온 28MB짜리 3D 반바지 파일을 방문자가 볼 때마다 Supabase에서 내려받다 보니 한도를 금방 넘겼습니다.

그래서 이렇게 나눕니다.

| 무엇 | 어디로 | 이유 |
|---|---|---|
| 표 데이터(주문·구독·프로필·옷장 목록·방문 기록 등) | **새 Supabase 프로젝트** | 용량이 작고, 코드를 거의 안 고쳐도 됨 |
| 기존 금색 반바지 3D 파일·썸네일 | **사이트 폴더** `public/wardrobe-assets/` | 기본 옷들과 같은 방식. Render가 직접 내려줌 |
| 앞으로 사용자가 올리는 3D 파일·커뮤니티 이미지 | **Cloudflare R2** | 저장 10GB 무료, 내려받는 전송량 무제한 무료 |

R2를 설정하지 않으면 예전처럼 새 Supabase Storage에 올라갑니다. 그래도 사이트는 동작하지만, 같은 한도 문제가 다시 생길 수 있으니 R2 설정을 권장합니다.

---

## 1. 새 Supabase 프로젝트 만들기 (약 10분)

1. **다른 구글 계정**으로 <https://supabase.com> 에 가입합니다. 무료 한도는 계정(조직) 단위라, 같은 조직에 프로젝트를 새로 만들면 한도가 그대로 공유됩니다.
2. **New project**를 누르고 아래처럼 만듭니다.
   - Region: **Northeast Asia (Seoul)**
   - Database Password: 아무 긴 비밀번호 (따로 적어 두세요)
3. 왼쪽 메뉴 **SQL Editor**로 갑니다.
   1. 저장소의 `supabase/schema.sql` 내용을 통째로 붙여넣고 **Run**을 누릅니다. 표 8개가 생깁니다.
   2. 따로 받은 `unexposed-data-migration.sql`을 붙여넣고 **Run**을 누릅니다. 관리자 5명, 프로필 5명, 방문 기록 148줄, 옷장 아이템 7개가 옮겨집니다.
      - 이 파일에는 이메일·연락처·주소 같은 **개인정보**가 들어 있습니다. GitHub에 올리지 마세요.
      - 두 파일 모두 여러 번 실행해도 데이터가 두 번 들어가지 않습니다.
4. **Storage**로 가서 **New bucket**을 두 번 만듭니다. 둘 다 **Public bucket**을 체크합니다.
   - `wardrobe-assets`
   - `community-assets`

   R2를 쓰면 실제로는 쓰이지 않지만, R2 설정 전에도 업로드가 되도록 만들어 둡니다.
5. **Project Settings → Data API**에서 **Project URL**을 복사합니다. **Project Settings → API Keys**에서 **Secret key**(`sb_secret_…`)를 복사합니다.

## 2. Cloudflare R2 만들기 (약 10분)

1. <https://dash.cloudflare.com> 에 가입하고 왼쪽 메뉴에서 **R2 Object Storage**로 들어갑니다.
   - 처음 켤 때 결제 수단(카드) 등록을 요구합니다. 무료 범위(저장 10GB, 쓰기 100만 회/월, 읽기 1000만 회/월) 안에서는 요금이 나가지 않습니다.
2. **Create bucket**에서 이름을 `unexposed-uploads`로 하고, 위치는 Automatic으로 둡니다.
3. 버킷의 **Settings**에서 두 가지를 설정합니다.
   - **Public access → R2.dev subdomain → Allow**를 켭니다. 그러면 `https://pub-…r2.dev` 주소가 나오는데, 이 주소를 복사합니다.
   - **CORS policy → Edit**에 아래를 붙여넣습니다. `https://사이트주소`는 실제 사이트 주소로 바꿉니다(예: `https://unexposed.onrender.com`). 3D 뷰어가 다른 주소에서 파일을 읽으려면 꼭 필요합니다.

     ```json
     [
       {
         "AllowedOrigins": ["https://사이트주소"],
         "AllowedMethods": ["GET", "HEAD"],
         "AllowedHeaders": ["*"],
         "MaxAgeSeconds": 86400
       }
     ]
     ```

4. R2 첫 화면 오른쪽의 **Account ID**를 복사합니다.
5. **Manage R2 API Tokens → Create API token**을 누르고 아래처럼 만듭니다.
   - Permissions: **Object Read & Write**
   - Specify bucket: `unexposed-uploads`만 선택

   만들면 **Access Key ID**와 **Secret Access Key**가 나옵니다. 이 화면을 닫으면 다시 볼 수 없으니 바로 복사해 두세요.

## 3. Render 환경변수 바꾸기

Render 대시보드에서 서비스를 고르고 **Environment**로 들어가 아래 값을 넣습니다.

| 이름 | 값 |
|---|---|
| `SUPABASE_URL` | 1-5의 Project URL (기존 값을 덮어쓰기) |
| `SUPABASE_SECRET_KEY` | 1-5의 Secret key (기존 값을 덮어쓰기) |
| `R2_ACCOUNT_ID` | 2-4의 Account ID |
| `R2_ACCESS_KEY_ID` | 2-5의 Access Key ID |
| `R2_SECRET_ACCESS_KEY` | 2-5의 Secret Access Key |
| `R2_BUCKET` | `unexposed-uploads` |
| `R2_PUBLIC_URL` | 2-3의 `https://pub-…r2.dev` (끝에 `/` 없이) |

**Save Changes**를 누르면 다시 배포됩니다. 배포 로그에 아래 줄이 보이면 R2가 연결된 것입니다.

```
업로드 파일 저장소: Cloudflare R2
```

> 순서가 중요합니다. **1-3의 데이터 옮기기를 먼저 한 뒤** 환경변수를 바꾸세요. 반대로 하면 서버가 빈 데이터베이스에 기본 옷장 아이템을 먼저 만듭니다. 그래도 데이터 옮기기 SQL이 그 아이템을 지우고 다시 넣기 때문에 결과는 같습니다.

## 4. 잘 됐는지 확인하기

- [ ] 메인 페이지가 열리고, 관리자 계정으로 로그인하면 관리자 페이지가 열린다.
- [ ] 관리자 페이지 → 접속자 통계에 예전 방문 기록이 보인다.
- [ ] 3D 꾸미기 → 옷장 둘러보기에 **금색 반바지**가 보이고, 입혀 보면 3D로 나온다.
- [ ] 옷장에 새 아이템(작은 .glb)을 올리면 썸네일과 3D가 보인다. 브라우저 개발자 도구에서 파일 주소를 보면 `pub-…r2.dev`로 시작한다.
- [ ] 커뮤니티에 이미지 한 장을 올리면 목록에 보인다.
- [ ] 제작 스튜디오에서 키를 넣고 주문하면, 관리자 페이지 주문 메모에 `체형: 키 …cm` 줄이 보인다.

## 참고: 서버 쪽에서 바뀐 점

- `server.js`: `R2_*` 다섯 값이 모두 있으면 `uploadFileToBucket()`이 R2에 업로드하고, R2 공개 주소를 돌려줍니다. 옷장 아이템을 지울 때는 R2 파일도 함께 지웁니다. 하나라도 비어 있으면 예전과 똑같이 Supabase Storage를 씁니다.
- R2에서는 버킷 하나에 `wardrobe-assets/…`, `community-assets/…` 폴더로 나눠 저장합니다.
- 신체 데이터 동의 여부와 스캔 기록은 원래부터 Supabase가 아니라 서버 디스크(JSON 파일)에 저장하고 있어서, 이번 이전과 관계없습니다.
